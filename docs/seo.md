# Local SEO engine

## Principle
Never publish thin pages. **One quality gate** (`src/lib/seo-engine.ts`) decides what is indexable; page `<meta robots>`, the sitemaps, the admin "index health" screen and the audit all call the same functions, so they cannot disagree.

## The gate
| Page | Indexed when |
|---|---|
| Area `/locations/{area}` | ≥ 3 **real** (non-sample, published) businesses **and** an original intro ≥ 100 characters |
| Category `/businesses/london/{category}` | same |
| Area × category `/locations/{area}/{category}` | ≥ 3 real businesses **and** (intro ≥ 100 chars **or** ≥ 5 businesses). Page exists only if ≥ 1 business |
| City hub `/businesses/london` | ≥ 3 real businesses |
| Business profile | real, published, not **thin** (thin = description < 100 chars *and* no phone/website/hours/services/photo/reviews) |
| Article / podcast / author | real (non-sample), published (authors need ≥ 1 real article) |
| Filtered/search directory, `?page=2+`, sample data, admin/owner/review-manage/claim-status pages | never (`noindex,follow`, self-canonical for pagination) |

Thresholds live in `seo-engine.ts` (`MIN_BUSINESSES`, `MIN_INTRO_CHARS`, `LOCCAT_RICH_COUNT`).

## Manual controls (Admin → SEO)
- **Index health**: every area/category/area×category page with real business count, intro length, status and *what it still needs* (e.g. "1 more real business", "Original intro of 100+ characters").
- **Per-page override** (`SeoPage`, keyed by path): title, meta description, **original intro** (shown on the page; this is how editors unlock indexing), and robots `AUTO | INDEX | NOINDEX`. `NOINDEX` always wins. `INDEX` overrides only the *thin-content* checks — an empty page (0 real businesses) can never be indexed. Live SERP preview and character counters.
- **Redirect manager** (`Redirect`): 308 permanent redirects. Loops refused, chains collapsed to one hop, only same-site targets (no open redirects), reserved paths refused, hit counts. **Created automatically** when a business or live article slug (or article type) changes.
- Moved-URL handling: dynamic pages call `redirectIfMoved(path)` before 404; a lowest-priority catch-all route handles everything else. Unknown URLs return a real 404 (noindex), never a soft 404.

## Sitemaps
`/sitemap.xml` is a **sitemap index** → `/sitemaps/{pages|locations|categories|businesses|articles|podcast|authors}-{n}.xml`, chunked at 5,000 URLs. Empty groups are omitted. `lastmod` is the real `updatedAt` (date only). Only gate-passing URLs; sample data never appears. `robots.txt` points at the index.

## Metadata & structured data
- Unique, data-driven titles/descriptions (auto-generated from real counts and categories, overridable). Pagination ≥ 2 is `noindex,follow`.
- JSON-LD: `Organization` (site), `BreadcrumbList` on every page, `CollectionPage` + `ItemList` on listing pages (only items visible on the page), `LocalBusiness` (name, address, phone, image, sameAs, areaServed, `openingHoursSpecification` from visible hours; `aggregateRating`/`Review` only from published reviews), `Article`/`NewsArticle`, `PodcastEpisode`, `Person`. Nothing is emitted that isn't visible on the page.
- Open Graph/Twitter cards everywhere; branded `opengraph-image` (black/yellow) for the site, every business profile and every article (generated by `next/og`).
- Search Console / Bing verification via `GOOGLE_SITE_VERIFICATION` / `BING_SITE_VERIFICATION` env vars (meta tags).

## Internal linking
Area page → its categories, other areas, stories. Category page → areas that have that category, other categories. Area×category → siblings (same area other categories, same category other areas) and parents. Business profile → area×category, area, category-city pages and related businesses. Hub pages ↔ articles ↔ businesses ↔ areas. No internal link points at the redirecting `/categories/{slug}` alias (audited).

## Audit (`npm run test:seo`)
Builds a realistic fixture (areas with/without intros, thin profile, reviews, articles, redirects), crawls the sitemap index, and checks every indexable URL: 200, no noindex, self canonical, unique title (10–70) and description (50–165), one H1, lang/viewport, OG tags, alt text, JSON-LD parses and **matches visible content**, breadcrumbs, internal links resolve, redirects are 308 single-hop, 404s are real, robots.txt, OG images render, RSS. Also asserts the *negative* cases (thin/under-threshold pages are noindex and absent from the sitemap). ~480 checks.

## Performance (Lighthouse, mobile, production build, local)
Performance 97 · Accessibility 100 · Best practices 100 on home, area, profile, article (LCP ≈ 2.7 s under simulated throttling, CLS 0, TBT ≈ 30 ms). Lighthouse "SEO" shows 66 on pages that feature sample data purely because they are intentionally `noindex` — expected until real data replaces it.

## Search pages
`/search`, `/saved`, `/newsletter/*`, `/api/*` are `noindex`/disallowed; search result pages are infinite near-duplicates. See docs/search.md.

## Not done / blocked
- **Search Console / Bing Webmaster**: needs the owner's Google/Microsoft account. After deploy: add the property, set the verification env var, submit `/sitemap.xml`.
- Real launch data and **original intros** for the launch boroughs/categories are what turn most pages from `noindex` to indexed (see Admin → SEO).
- IndexNow / instant indexing pings, image & news sitemaps, hreflang (single-language site) — not needed yet.
- Core Web Vitals field data (CrUX) only exists after launch.
